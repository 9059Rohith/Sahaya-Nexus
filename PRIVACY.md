# Privacy

Organization invitations are sent only as in-app notices to registered accounts. Access to an organization's resources and assigned requests begins only after the invited person accepts; the owner can revoke it. Owners can see team members' account names and email addresses.

The normal installation starts without user or activity records. People choose to submit a name, email, need text, optional coordinates, organization details and evidence. Blood requests are coordination records only and cannot enter public discovery. Only community and accessibility reports can opt into the public issue explorer; it omits their free-text description and exact location.

The requester and authorized staff can see exact request coordinates and evidence. An assigned responder can see the operational request. The public impact map rounds positions to 0.1° cells and suppresses cells with fewer than three verified outcomes. Staff map views round the point before loading an OpenStreetMap iframe. Map display can be disabled; the queue and area list remain usable. Exact coordinates are never sent to OpenStreetMap by the app.

Typed requests and images are stored in the database and private evidence volume. JPEG and PNG uploads are decoded and re-encoded without EXIF metadata. New PDF uploads are refused; any PDF evidence stored by earlier versions remains a private authenticated download. Speech audio is transcribed by a locally cached model and is not stored by the application. If Ollama is enabled, the request text is sent only to the configured local endpoint. The device saves unfinished draft text and accessibility preferences in local storage. If sending a reviewed request fails, one pending request is saved in local storage under the signed-in account ID, including its description and location. It is never sent automatically; the person must choose Send now after reconnecting or discard it. Account anonymization removes its local draft and pending request. Clear site data to erase device records on a shared device.

`DELETE /api/v1/auth/me` supports password-confirmed account anonymization for non-staff accounts after active work is closed. It removes personal profile fields, request description and location, evidence files, request message text, free-text feedback and notification records. Category, lifecycle timestamps and verified aggregate outcome units remain for accountability. Staff and organization owner accounts require an offboarding/transfer process. Audit metadata remains tied to a pseudonymous account ID; application audit payloads related to the account are cleared. The request owner can initiate this action from Profile and accessibility settings.

Age-based request-content retention is disabled by default. An administrator can set a 30–3650 day period in Platform policy after deciding the applicable legal schedule. The worker then removes personal text, exact location, evidence files, request messages, linked notification content and free-text outcome details from closed requests after that period; it keeps lifecycle status and verified aggregate impact. Open abuse cases delay this action. Account profiles and backups require separate schedules and procedures. Before public operation, the hosting organization must choose and publish these schedules, document legal obligations, and handle exports or erasure requests outside self-service deletion. Local backups must follow the same policy.
